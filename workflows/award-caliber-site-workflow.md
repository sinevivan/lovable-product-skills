# workflows/award-caliber-site-workflow.md  

## 🎯 Цель документа  
Создать **конечный, русскоязычный рабочий процесс** для разработки запоминающегося сайта‑приложения, ориентированного на **правду проекта и цель конверсии**. Процесс построен так, чтобы гарантировать **доступность, производительность, оригинальность и высокую конверсию**, при этом не обещая получения наград (Awwwards — только ориентир).

---

## 📋 Критерии входа  

| № | Требование | Как проверить |
|---|------------|----------------|
| 1 | Чётко сформулированная **правда проекта** (mission) и **цель конверсии** (e.g. лид‑ген, продажа) | Документ «Project Brief» с KPI |
| 2 | Бюджет и сроки согласованы с заказчиком | Подписанный контракт / план‑график |
| 3 | Наличие базовых бренд‑активов (логотип, фирменные цвета, шрифты) | Файлы в репозитории `assets/brand/` |
| 4 | Команда сформирована (PM, UX‑директор, UI‑дизайнер, фронтендер, QA) | Список участников в `README.md` проекта |
| 5 | Технические ограничения (CMS, хостинг, интеграции) задокументированы | Тех‑задание (Tech Spec) |

*Если хотя бы один пункт не выполнен – процесс **не стартует**.*

---

## 🚦 Обязательные ворота согласования  

| Ворота | Участники | Критерий «принятия» | Выход |
|--------|-----------|----------------------|-------|
| **0️⃣ Инициатива** | PM, Заказчик | Подтверждённые правды проекта + цель конверсии | Запуск Workflow |
| **1️⃣ Концепт‑директор** | UX‑директор, PM | Одобрение **одного** из трёх концептуальных территорий | Переход к визуальному миростроению |
| **2️⃣ Визуальное миростроение** | UI‑дизайнер, PM | Прототипы world‑building, согласованные с бренд‑гайдом | Переход к направлению скролла/интеракций |
| **3️⃣ Критика P0** | Внутренняя эксперт‑группа | Наличие «непримиримых» проблем → их устранение | Переход к архитектуре конверсии |
| **4️⃣ Архитектура конверсии** | Conversion‑Architect, PM | Точки касания, CTA‑мэппинг, KPI‑трекинг | Переход к фронтенд‑рефайнменту |
| **5️⃣ Финальная QA** | QA‑lead, Accessibility‑specialist | 100 % покрытие критериев доступности, адаптивности, performance‑budget | Готово к релизу |

---

## 🛑 Условия остановки  

1. **Нарушение бюджета** (время > 30 % от планового) – пересмотр планов.  
2. **Критические проблемы доступности** (WCAG 2.2 A/AA) – обязательный фикс до следующего шага.  
3. **Потеря оригинальности** – обнаружение копирования (см. правило Anti‑Copying).  
4. **Отказ заказчика** от любой из одобренных территорий – возврат к шагу 1.  

---

## 📊 Сложность и бюджет производительности  

| Показатель | Ограничение |
|------------|--------------|
| **Время загрузки (LCP)** | ≤ 2.5 сек (desktop), ≤ 3.0 сек (mobile) |
| **Общий вес страницы** | ≤ 1.5 МБ (без кеша) |
| **Количество запросов** | ≤ 30 HTTP‑запросов |
| **Код‑сложность** | React ≤ 15 компонентов в hero‑slice, Tailwind‑utility ≤ 200 классов |
| **Анимации** | Reduced‑motion‑compatible, длительность ≤ 300 мс, без jank |

---

## 🚫 Правило Anti‑Copying  

> **Никакие визуальные или интерактивные решения не могут копировать** существующие сайты, известные бренды или шаблоны.  
> При каждом этапе **визуального миростроения** и **генеративного ассет‑дирекшна** проводится проверка на уникальность (Reverse Image Search, сравнение с UI‑паттернами). Любое совпадение > 15 % → обязательный редизайн.

## 🛠️ Шаги рабочего процесса  

### 0️⃣ Инициатива – «Project Truth & Conversion Goal»  
**Описание:** Формулирование миссии проекта и KPI‑конверсии.  
**Prompt (готовый к копированию):**  
```
Ты – продакт‑менеджер. Сформулируй миссию проекта в 2‑3 предложения и укажи главную цель конверсии (например, 5 % рост заявок). Приведи 3 измеримых KPI.
```  

---

### 1️⃣ Концепт‑директор – «Memorable Concept Director»  
**Описание:** Генерация трёх концептуальных территорий (настроение, сюжет, визуальная метафора).  
**Prompt:**  
```
Создай три уникальные концептуальные территории для сайта, учитывая миссию проекта и цель конверсии. Для каждой опиши: тему, эмоциональный тон, ключевые визуальные метафоры, примерный пользовательский путь.
```  

**Выбор:** Заказчик/PM выбирает одну территорию → переход к следующему вороту.  

---

### 2️⃣ Визуальное миростроение – «Visual Worldbuilding»  
**Описание:** Детальная проработка мира (цветовая палитра, типографика, иллюстрации, микросхемы).  
**Prompt:**  
```
На основе выбранной территории создай mood‑board: 5‑7 цветов, 2‑3 шрифта, 3‑4 стилистических референса (без копирования). Оформи в Figma‑файл.
```  

---

### 3️⃣ Направление скролла/интеракций – «Scroll / Interaction Direction»  
**Описание:** Определение схемы прокрутки (одностраничный, секционный), микровзаимодействий, анимаций.  
**Prompt:**  
```
Опиши скролл‑стратегию сайта (например, вертикальный парраллкс, секционный скролл). Перечисли 5 микровзаимодействий, совместимых с reduced‑motion.
```  

---

### 4️⃣ Генеративный ассет‑дирекшн – «Generative Asset Direction» *(по необходимости)*  
**Описание:** При необходимости – генерация иллюстраций, 3D‑моделей, SVG‑иконок через AI‑инструменты.  
**Prompt:**  
```
Сгенерируй 3 уникальные SVG‑иллюстрации в стиле [выбранная территория], без использования готовых шаблонов. Укажи prompt для Midjourney/DALL·E.
```  

---

### 5️⃣ Представительный срез – «Representative Slice»  
**Элементы:**  
- **Hero** (desktop + mobile)  
- **Narrative Transition** (переход к истории)  
- **Proof Module** (кейсы, отзывы)  
- **Primary CTA** (кнопка, форма)  

**Prompt:**  
```
Создай макет hero‑section для desktop (1440 px) и mobile (375 px) с учётом reduced‑motion. Включи заголовок, подзаголовок, визуал, CTA. Добавь loading‑state и анимацию появления.
```  

---

### 6️⃣ Некомпромиссная критика – «Uncompromising Critique»  
**Описание:** Внутренняя ревью всех созданных артов и прототипов. Фокус на **доступность, оригинальность, производительность**.  
**Prompt:**  
```
Проведи критический обзор представленного hero‑slice: проверь контраст WCAG AA, размер шрифтов, количество запросов, уникальность визуала. Составь список правок.
```  

---

### 7️⃣ Закрытие P0 – «Close P0»  
**Описание:** Устранение всех критических (P0) проблем, выявленных на предыдущем этапе.  

---

### 8️⃣ Выравнивание с архитектором конверсии – «Landing Conversion Architect Alignment»  
**Описание:** Совместное построение карты конверсий, размещение CTA, A/B‑гипотез.  
**Prompt:**  
```
Составь карту пользовательского пути от входа до Primary CTA. Укажи 3 точки измерения (click, scroll depth, form submit) и предложи 2 A/B‑гипотез.
```  

---

### 9️⃣ Уникальная фронтенд‑отшлифовка – «Distinctive Frontend Refinement»  
**Описание:** Применение React + Tailwind, кастомных хуков, анимаций с Framer Motion (с учётом reduced‑motion).  

---

### 🔟 Дизайн‑система – «Design System»  
**Описание:** Создание компонентов (Button, Card, Modal) в Storybook, документирование токенов (цвет, spacing).  

---

### 1️⃣1️⃣ Реализация – «React / Tailwind Implementation»  
**Описание:** Кодирование всех секций, подключение CMS/API, настройка сборки (Vite/Webpack).  

---

### 1️⃣2️⃣ QA – «Accessibility / Responsive QA»  
**Тесты:**  
- WCAG 2.2 AA (axe, Lighthouse)  
- Responsive (breakpoints 320‑2560)  
- Performance (Lighthouse ≥ 90)  
- Reduced‑motion (prefers‑reduced‑motion)  

---

### 1️⃣3️⃣ Финальная критика релиза – «Release Critique»  
**Описание:** Публичный демо‑ревью, сбор обратной связи, план пост‑релизных улучшений.  

---

## ✅ Definition of Done (DoD)

| Критерий | Требование |
|----------|------------|
| **Документация** | Все этапы задокументированы в `docs/` (Brief, Concept, Specs). |
| **Концепт** | Одобрена одна территория, остальные отклонены. |
| **Визуалы** | Mood‑board, world‑building, UI‑мокапы без копий, проверены на уникальность. |
| **Прототип** | Интерактивный Figma‑прототип с описанными микровзаимодействиями. |
| **Код** | React ≥ 18, Tailwind ≥ 3, покрытие unit‑тестов ≥ 80 %, lint‑чистый. |
| **Доступность** | WCAG 2.2 AA, проверка axe, отсутствие ошибок в консоли. |
| **Производительность** | LCP ≤ 2.5 s (desktop), ≤ 3 s (mobile), общий вес ≤ 1.5 MB, запросов ≤ 30. |
| **Конверсия** | Настроены метрики, минимум 2 A/B‑гипотез в продакшн. |
| **Релиз** | Deploy в прод без ручных правок, готов к мониторингу. |
| **Согласования** | Все ворота (0‑5) пройдены, подписи в `APPROVALS.md`. |

*Только при полном соответствии DoD проект считается **готовым к запуску**.*
