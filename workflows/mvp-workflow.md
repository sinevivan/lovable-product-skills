# MVP‑Workflow (рабочий процесс создания минимального жизнеспособного продукта)

> **Цель:** Последовательный, проверяемый процесс от начального исследования до аудитов, позволяющий быстро и качественно выводить MVP на рынок. Все этапы описаны на русском языке, включают критерии входа, контрольные точки (approval gates), условия остановки и готовые стартовые подсказки для копирайтеров/аналитиков.

---

## 📋 Сводка процесса

| № | Этап | Краткое описание | Ключевой артефакт |
|---|------|------------------|-------------------|
| 1 | **Синтез исследований** (Discovery Synthesis) | Сбор и агрегация уже существующих доказательств (данные, интервью, аналитика). | **Research Synthesis Report** |
| 2 | **Jobs‑to‑Be‑Done (JTBD)** | Формулирование пользовательских задач и желаемых результатов. | **JTBD Canvas** |
| 3 | **Конкурентный интеллект** (Competitive Intelligence) | При необходимости – анализ конкурентов, рыночных ниш и альтернатив. | **Competitive Landscape Matrix** |
| 4 | **Определение объёма MVP** (MVP Scope) | Выбор минимального набора функций, покрывающих ключевые JTBD. | **MVP Scope Document** |
| 5 | **PRD (Product Requirements Document)** | Детальное описание требований, критериев приёмки и метрик успеха. | **PRD** |
| 6 | **Аналитика** (Analytics) | Планирование метрик, событий и KPI для измерения MVP. | **Analytics Specification** |
| 7 | **Дизайн‑направление** (Design Direction) | Выбор стилистики, пользовательских потоков и прототипов. | **Design Brief** |
| 8 | **Система дизайна** (Design System) | Создание компонентов, гайдлайнов и UI‑кита. | **Design System Library** |
| 9 | **Гарды реализации** (Implementation Guardrails) | Технические ограничения, стандарты кода, CI/CD, security. | **Implementation Guardrails Checklist** |
|10| **Аудиты** (Audits) | Проверка соответствия требованиям, юзабилити, security, performance. | **Audit Report** |

## 1️⃣ Синтез исследований (Discovery Synthesis)

### Критерии входа
- Наличие хотя бы **3 независимых источников** доказательств (интервью, аналитика, рыночные отчёты).  
- Данные актуальны (не старше **12 мес**).  
- Заказчик/стейкхолдеры подтвердили готовность к дальнейшему анализу.

### Выходные артефакты
- **Research Synthesis Report** (резюме, инсайты, открытые вопросы).

### Approval Gate
- **Stakeholder Review**: 2‑х из 3 ключевых стейкхолдеров подписывают «Ready for JTBD».

### Условия остановки
- Недостаточно достоверных данных → переход к **Этапу 1‑a: Дополнительные исследования** (переходим к новому циклу).

### Стартовая подсказка (copy‑ready)
```
Опишите, какие доказательства (интервью, аналитика, отчёты) уже собраны по проблеме. Укажите их актуальность и основные инсайты, которые могут влиять на формирование MVP.
```

---

## 2️⃣ Jobs‑to‑Be‑Done (JTBD)

### Критерии входа
- Завершённый **Research Synthesis Report**.  
- Подтверждена готовность к формулированию задач (Approval Gate 1 пройден).

### Выходные артефакты
- **JTBD Canvas** (Job Statement, Desired Outcome, Pain Points, Success Criteria).

### Approval Gate
- **Product Owner + UX Lead** согласовывают, что все ключевые пользовательские задачи покрыты.

### Условия остановки
- Выявлены **противоречивые JTBD** → требуется уточнение в **Этапе 1** (обратный цикл).

### Стартовая подсказка
```
Сформулируйте Job‑to‑Be‑Done в формате: «Когда [контекст], я хочу [действие], чтобы [результат]». Приведите 3‑5 самых критичных JTBD.
```

---

## 3️⃣ Конкурентный интеллект (Competitive Intelligence) – при необходимости

> **Триггер:** Если в JTBD обнаружены «потенциальные угрозы» или «неизвестные альтернативы».

### Критерии входа
- Одобренный **JTBD Canvas**.  
- Выявлен минимум **1 потенциальный конкурент/альтернатива**.

### Выходные артефакты
- **Competitive Landscape Matrix** (позиционирование, сильные/слабые стороны, ценовые модели).

### Approval Gate
- **Strategy Lead** утверждает, что получена достаточная картина рынка.

### Условия остановки
- Нет значимых конкурентов → пропустить этап.

### Стартовая подсказка
```
Составьте таблицу конкурентов с колонками: Продукт, Ценовая модель, Ключевые функции, Преимущества, Недостатки. Оцените, какие из их функций могут стать «must‑have» для нашего MVP.
```

---

## 4️⃣ Определение объёма MVP (MVP Scope)

### Критерии входа
- **JTBD Canvas** (и, если применимо, Competitive Matrix) утверждены.  
- Согласованы бизнес‑цели (time‑to‑market, бюджет).

### Выходные артефакты
- **MVP Scope Document** (список функций, приоритеты, критерии «инклюзии»/«исключения»).

### Approval Gate
- **Product Owner + Engineering Lead** подписывают «Scope Locked».

### Условия остановки
- Превышение **budget‑cap** или **time‑to‑market** → требуется пересмотр приоритетов (итерация с этапом 2).

### Стартовая подсказка
```
Перечислите функции, которые непосредственно решают топ‑3 JTBD. Укажите приоритет (Must, Should, Could) и оценку усилий (Low/Medium/High).
```

---

## 5️⃣ PRD (Product Requirements Document)

### Критерии входа
- Утверждённый **MVP Scope Document**.  

### Выходные артефакты
- **PRD** (функциональные требования, пользовательские сценарии, критерии приёмки, KPI).

### Approval Gate
- **QA Lead + Product Owner** подтверждают полноту и измеримость требований.

### Условия остановки
- Неопределённые критерии приёмки → возврат к **Этапу 4**.

### Стартовая подсказка
```
Опишите каждый функциональный пункт из MVP Scope: цель, пользовательский сценарий, критерий приёмки, метрика успеха.
```

---

## 6️⃣ Аналитика (Analytics)

### Критерии входа
- Готовый **PRD**.  

### Выходные артефакты
- **Analytics Specification** (события, свойства, дашборды, целевые KPI).

### Approval Gate
- **Data Analyst + Product Owner** согласуют набор метрик.

### Условия остановки
- Противоречия в измеримых KPI → возврат к **Этапу 5**.

### Стартовая подсказка
```
Сформулируйте список событий (Event) и параметров (Property), которые необходимо фиксировать для каждой ключевой функции MVP. Укажите целевые значения KPI.
```

---

## 7️⃣ Дизайн‑направление (Design Direction)

### Критерии входа
- Утверждённый **Analytics Specification**.  

### Выходные артефакты
- **Design Brief** (стилистика, пользовательские потоки, low‑fi прототипы).

### Approval Gate
- **UX Lead + Brand Manager** одобряют визуальное и интерактивное направление.

### Условия остановки
- Несоответствие брендовым гайдлайнам → возврат к **Этапу 7‑a** (переработка концепции).

### Стартовая подсказка
```
Опишите желаемый визуальный стиль (цвета, типографика) и основные пользовательские потоки для топ‑3 функций MVP.
```

---

## 8️⃣ Система дизайна (Design System)

### Критерии входа
- Утверждённый **Design Brief**.  

### Выходные артефакты
- **Design System Library** (компоненты, токены, документация).

### Approval Gate
- **Design System Owner + Front‑End Lead** подтверждают готовность к использованию в разработке.

### Условия остановки
- Отсутствие согласованных токенов → возврат к **Этапу 7**.

### Стартовая подсказка
```
Создайте список UI‑компонентов (Button, Input, Card и т.д.) с их состояниями и токенами (цвет, отступ, типографика). Приведите ссылки на Figma/Sketch файлы.
```

---

## 9️⃣ Гарды реализации (Implementation Guardrails)

### Критерии входа
- Доступна **Design System Library** и **PRD**.  

### Выходные артефакты
- **Implementation Guardrails Checklist** (код‑стайл, CI/CD, security, performance‑budget).

### Approval Gate
- **Engineering Manager + Security Lead** подписывают «Ready for Development».

### Условия остановки
- Нарушения в security‑audit → возврат к **Этапу 9‑a** (корректировка).

### Стартовая подсказка
```
Перечислите обязательные правила код‑стайла, CI‑проверки и ограничения по размеру/скорости для каждой функции MVP.
```

---

## 🔟 Аудиты (Audits)

### Критерии входа
- Завершённый спринт разработки и деплой MVP в staging/production.  

### Выходные артефакты
- **Audit Report** (UX‑audit, security‑audit, performance‑audit, compliance).

### Approval Gate
- **Product Owner + QA Lead** подтверждают, что MVP прошёл все аудиты и готов к запуску.

### Условия остановки
- Критические дефекты → возврат к соответствующим этапам (UX → 7, Security → 9, Performance → 9).

### Стартовая подсказка
```
Сформулируйте чек‑лист аудита: 1) UX‑соответствие JTBD, 2) уязвимости OWASP, 3) время загрузки < 2 сек, 4) соответствие GDPR/CCPA.
```

## 📌 Общие правила переходов

| Текущее состояние | Следующее состояние | Требуемый результат |
|-------------------|---------------------|---------------------|
| **Discovery** → **JTBD** | При наличии достаточных инсайтов |
| **JTBD** → **Competitive** | При обнаружении угроз/альтернатив |
| **Competitive** → **MVP Scope** | После согласования конкурентных выводов |
| **MVP Scope** → **PRD** | При подтверждённом бюджете/таймлайн |
| **PRD** → **Analytics** | При наличии измеримых KPI |
| **Analytics** → **Design Direction** | После согласования метрик |
| **Design Direction** → **Design System** | При одобрении стилистики |
| **Design System** → **Implementation Guardrails** | При готовой библиотеке компонентов |
| **Implementation Guardrails** → **Audits** | После завершения разработки и деплоя |
| **Audits** → **Release** | При отсутствии критических замечаний |
