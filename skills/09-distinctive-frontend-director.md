# Display Name
Distinctive Front‑End Art Direction

## Name
distinctive-frontend-director

## Description
Generate three structurally distinct visual directions for a front‑end product, each defined by typography, composition, color, texture, imagery, motion, accessibility, and cost. Recommend the optimal direction, and deliver a concrete “slice” (a mock‑up of a key UI component) that can be handed off to the UI‑Implementation skill for rapid prototyping.

## Instructions

### Objective
Produce a concise, evidence‑aware art‑direction brief that enables designers and developers to move from concept to a validated visual slice without ambiguity. The brief must articulate three mutually exclusive visual systems, justify the recommended system with data‑driven rationale, and provide a ready‑to‑implement component mock‑up (e.g., a hero banner or card) that respects the chosen direction’s rules.

### Use when
- A new product or major redesign requires a clear, non‑generic visual identity.
- Stakeholders need a side‑by‑side comparison of distinct visual strategies before committing resources.
- The design team seeks a concrete, testable slice to validate assumptions with users or developers.

### Do not use when
- The brand already has an established visual language that must be preserved verbatim.
- Only minor UI tweaks are required; a full art‑direction exercise would be overkill.
- The project is in a “code‑first” phase where visual decisions are deferred until after functional MVP validation.

### Required inputs
1. **Product context** – brief description of the product, target audience, and primary use cases.  
2. **Brand assets** – existing logo, color palette (if any), typography files, and brand guidelines.  
3. **Accessibility mandate** – WCAG level required (AA or AAA) and any specific assistive‑technology considerations.  
4. **Budget tier** – Low (≤ $5k), Medium ($5k‑$15k), High (> $15k).  
5. **Timeline** – desired date for the slice handoff.

### Workflow
1. **Contextual analysis (≈ 10 min)** – parse inputs, surface any constraints (e.g., brand‑locked colors).  
2. **Research synthesis (≈ 15 min)** – pull recent case studies, pattern libraries, and accessibility audits relevant to the audience and budget.  
3. **Direction generation (≈ 20 min)** – craft three distinct visual systems (A, B, C) with a table summarizing each attribute (typography, composition, etc.).  
4. **Recommendation matrix (≈ 10 min)** – score each direction against cost, accessibility, brand fit, and innovation; select the top‑scoring direction.  
5. **Slice creation (≈ 15 min)** – design a high‑fidelity mock‑up of a representative component (e.g., hero banner) using the chosen system’s assets.  
6. **Hand‑off packaging (≈ 5 min)** – export the slice as a Figma link or Sketch file, attach a style‑guide excerpt, and annotate any dynamic specifications for the UI‑Implementation skill.

### Output contract
- **Three direction cards** – each card includes a concise paragraph and a 2‑column table (attributes vs. values).  
- **Recommendation summary** – includes a score table, rationale, and risk assessment.  
- **Representative slice** – a downloadable design file link, annotated with component dimensions, interaction states, and accessibility notes.  
- **Hand‑off checklist** – items required by the downstream UI‑Implementation skill (e.g., token list, motion spec JSON).

### Quality gate
- **Clarity** – each direction must be distinguishable without visual overlap; terminology is consistent across cards.  
- **Evidence** – at least one external reference (case study, design system) per direction.  
- **Accessibility compliance** – all color choices meet the specified WCAG contrast ratio; typography includes legible sizes for the target audience.  
- **Cost realism** – cost estimates are grounded in industry averages for assets (stock imagery, custom illustration, motion design).  
- **Hand‑off completeness** – the slice includes all tokens (color, spacing, typography) required for immediate development.

### Safety constraints
- Do not fabricate brand assets; if required assets are missing, flag the deficiency and request clarification.  
- Avoid recommending motion that could trigger vestibular disorders; any animation must respect the “reduce motion” preference in user settings.  
- Ensure all imagery is royalty‑free or properly licensed; include attribution metadata where needed.  
- Do not exceed the supplied budget tier; any recommendation that would breach the budget must be clearly labeled as “out‑of‑scope”.  
- Preserve user privacy – no personal data should be embedded in mock‑ups or documentation.
