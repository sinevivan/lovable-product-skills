# docs/lovable-setup-and-simple-prompts.md  

## 📋 Быстрый порядок настройки  

1. **Workspace Knowledge**  
   - Откройте *Lovable Workspace Knowledge* и **вставьте** содержимое `workspace-knowledge.md`.  
   - Это фон, который всегда доступен, но не отображается в UI.  

2. **Установка навыков**  
   - В разделе *Skills* установите **все 23 навыка**.  
   - Для каждого навыка укажите **точно**:  
     - **Name** – как в шаблоне.  
     - **Description** – как в шаблоне.  
     - **Instructions** – как в шаблоне.  
   - После установки навыки будут загружаться **по запросу** (on‑demand).  

3. **Автоматическое использование навыков**  
   - Перейдите в *Workspace Settings* → *Automation* и **включите** опцию *Automatic skill use*.  

4. **Project Knowledge**  
   - Создайте новый проект и **импортируйте** `project-knowledge-template.md` в *Project Knowledge*.  
   - Ограничение: **до 10 000 символов**. Делайте записи лаконичными.  

5. **Запуск в режиме План**  
   - Перейдите в *Plan Mode* и отправьте **естественный простой запрос** (см. примеры ниже).  

---

## ⚙️ Как работает Lovable  

| Слой | Что делает | Где хранится |
|------|------------|--------------|
| **Workspace Knowledge** | Фоновая справочная информация, доступна всем проектам. | В Workspace Knowledge (не видна в UI). |
| **Project Knowledge** | Конкретные детали текущего проекта (макс 10 k символов). | В Project Knowledge. |
| **Skills** | Выполняют отдельные задачи (генерация кода, проверка и т.п.). | Загружаются **по запросу**. |
| **Plan → Agent → Execute** | Последовательные режимы, в которых Lovable переключается автоматически. | UI отображает текущий режим. |

## 🪄 Примеры простых запросов  

| Запрос | Ожидаемый переход режима | Что покажет Lovable |
|--------|--------------------------|---------------------|
| `Сделай запоминающийся сайт для стартапа, используя React и Tailwind.` | **Plan → Agent** | План проекта, список задач, предложения UI/UX. |
| `Придумай концепцию рекламной кампании для продукта X.` | **Plan** | Краткое описание концепции, целевая аудитория. |
| `Продолжай` | **Agent** (продолжение текущей задачи) | Дальнейшее развитие уже сгенерированного контента. |
| `Выбираю вариант 2` | **Agent** (выбор из предложенных вариантов) | Применение выбранного варианта, переход к следующей задаче. |
| `Собирай утверждённый фрагмент` | **Execute** | Сборка финального артефакта (код, текст, дизайн). |
| `Проверь результат` | **Execute** | Тестирование/валидация собранного результата, вывод отчёта. |

---

## 🔄 Ожидаемое переключение режимов  

1. **Plan** – формируется общий план, пользователь выбирает/корректирует.  
2. **Agent** – Lovable использует нужные навыки, генерирует детали.  
3. **Execute** – финальная сборка и проверка.  

В UI каждый режим обозначается отдельной панелью/заголовком.

## 🛠️ Устранение типовых проблем  

| Проблема | Возможные причины | Что сделать |
|----------|-------------------|-------------|
| **Неправильный навык активировался** | Ошибка в `Name/Description/Instructions` при установке. | Проверьте точность полей в Skills, переустановите при необходимости. |
| **Состояние потеряно после переключения** | Автосохранение отключено в настройках Workspace. | Включите *Auto‑save* в *Workspace Settings*. |
| **Lovable начинает строить слишком рано** | Автоматическое использование навыков включено, но запрос слишком короткий. | Добавьте уточняющий контекст в запрос или временно отключите *Automatic skill use*. |
| **Запускается только один этап** (Plan → Agent → Execute) | Это **намеренно** для быстрых проверок (см. smoke‑test). | Для полного цикла отключите *Single‑stage mode* в настройках. |

## 🚀 Smoke‑test (без изменения кода)  

```text
Тестовый запрос: «Создай короткую структуру сайта‑портфолио из трёх страниц и выведи план реализации». 
```

- Ожидается: переход **Plan → Agent → Execute**, вывод плана, генерация кода и финальная проверка.  
- Если любой из этапов пропускается – проверьте настройки автоматизации и наличие всех 23 навыков.
